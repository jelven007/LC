# 生命倒计时 · Life Countdown

微信小程序。用年 / 季 / 月 / 周 / 天五个维度划分人生阶段，管理目标与周期提醒，并可视化人生进度。

> 核心的情绪价值不是"督促你努力"，而是**让你看见时间的形状**。

---

## 功能

| 模块 | 说明 |
|---|---|
| **今日** | 今日概览、人生进度格子图、即将到期的阶段与今日提醒 |
| **阶段** | 按年 / 季 / 月 / 周 / 天划分阶段，5 套模板一键套用 |
| **提醒** | 支持一次性 / 每日 / 每周 / 每月 / 自定义间隔五种周期 |
| **回顾** | 30 / 90 天趋势柱状图、阶段完成度统计 |
| **我的** | 人生进度设置、多账户切换、备份导入导出、云同步诊断 |

- **三色时间语义**：过去=米黄、现在=橙红、未来=紫，全局统一
- **亮暗双主题**：跟随系统 `prefers-color-scheme` 自动切换
- **本地优先 + 云同步**：不登录也能用全部功能；登录后跨设备同步

## 技术栈

微信小程序原生开发 + 微信云开发（CloudBase），无第三方框架。

```
miniprogram/          小程序源码（miniprogramRoot）
├── app.js / app.json / app.wxss
├── config.js         唯一需要手改的配置（云环境 ID、备案号）
├── theme.json        亮/暗主题变量
├── pages/            8 个页面
├── components/       隐私弹窗组件
├── utils/            核心逻辑
└── images/

cloudfunctions/
└── login/            取 OPENID 的云函数
```

### 分层约定

```
time.js  (UTC 天序号，防时区/夏令时误差 — 纯计算)
   ↓
model.js (视图计算，全部纯函数，可单测)
   ↓
store.js (持久化 + 多租户 + 云同步)
   ↓
pages/*  (只做数据搬运与 setData，不写业务逻辑)
```

| 文件 | 行数 | 职责 |
|---|---|---|
| `utils/time.js` | 196 | 日期工具。天序数用 UTC 计算，避免夏令时导致的差一天 |
| `utils/model.js` | 405 | 所有视图计算，纯函数，无副作用 |
| `utils/store.js` | 774 | 多租户存储、脏数据归一化、云端双向合并 |
| `utils/cloud.js` | 186 | 云同步层，单文档按 openid 隔离 |
| `utils/constants.js` | 132 | 维度、颜色、周期类型、阶段模板 |
| `utils/share.js` | 43 | 分享文案生成 |

## 快速开始

### 1. 用微信开发者工具打开

```
项目根目录：本仓库根目录（不要选 miniprogram/）
```

`project.config.json` 已配置好 `miniprogramRoot` 与 `cloudfunctionRoot`，工具会自动识别。

> 若提示「目录结构变化，是否信任」，点**信任**。

### 2. 不配置云开发也能跑

直接编译即可。此时为**纯本地模式**，全部功能可用，只是不跨设备同步。

### 3. 启用云同步（可选）

1. 开发者工具 → 顶部「云开发」→ 创建环境
2. 云开发控制台 → 设置 → 复制**环境 ID**
3. 填入 `miniprogram/config.js` 的 `cloudEnv`
4. 数据库建两个集合：

   | 集合 | 权限（**必须**选「简易权限控制」） |
   |---|---|
   | `lc_userdata` | 仅创建者可读写 |
   | `lc_users` | 仅管理端可读写 |

   > 不要选「自定义安全规则」——该模式下 `doc(id).set()` 不可用，会表现为「登录成功但数据不同步」且不报明显错误。
5. 右键 `cloudfunctions/login` → 上传并部署（云端安装依赖）
6. 重新编译 → 进「我的」页 → 运行**云同步诊断**，三行全绿即成功

## 设计决策记录

几个不做的事，以及原因。

**天序数用 UTC 算**

`new Date('2026-10-18')` 在东八区解析为 UTC 零点，本地时间却是 08:00；夏令时地区更乱。统一转成 UTC 天序号做整数差，日期比较就不会差一天。

**WXML 里不做算术**

曾经在模板里写 `expectYears - years - 1`，出生年份早于设定年限时会渲染出「未来 -47 格」这种文案。现在所有边界值都在 `model.js` 里收敛好再传给视图。

**首次绑微信用内容量比较，而非时间戳**

真实场景：用户换新手机 → 看到示例数据 → 随手填了个出生日期 → 才想起来登录。这时本机时间戳是最新的，按时间戳判定就会把示例数据推上云端，**覆盖掉真实数据**。所以示例数据带 `_demo` 标记（用户任何改动自动清除），权重记 0，首次绑定按内容量择优。

**集合权限必须用简易权限控制**

见上文第 3 步。这是本项目最容易踩的坑。

## 文案口径约定

审核对工具类小程序看**表达方式**多于功能本身。有同类产品因「死亡倒计时」被判定传播焦虑而驳回。

| 不使用 | 使用 |
|---|---|
| 约剩 X 天 | 未来 X 天 |
| 预期寿命 | 预期年限 |
| 生命进度 | 人生进度 |

原则：**只陈述已完成的时间统计与未来天数，不做生存期预测。**
